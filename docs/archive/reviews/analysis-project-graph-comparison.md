# Code Mind vs Project Graph (graphif) 双向对比分析

## 项目概览

| 维度 | Code Mind | Project Graph (graphif) |
|------|-----------|------------------------|
| 定位 | 本地优先思维导图 + AI 协作 API | 桌面级节点图绘制工具 |
| Stars | 新项目 | 4,100+ |
| 技术栈 | Go + Vite/TypeScript + Wails | TypeScript + React + Tauri |
| 渲染引擎 | DOM 渲染 | Canvas 2D |
| 桌面框架 | Wails (Go) | Tauri (Rust) |
| 数据格式 | JSON 文件 | .prg (ZIP + MessagePack) |
| 图类型 | 树形思维导图 + 关系线 | 任意有向图/DAG/树/网络 |
| 版本 | v1.6 | v3.0.4 (205 releases) |
| 贡献者 | 个人项目 | 30+ 贡献者 |

---

## 一、Project Graph 的优势（Code Mind 可借鉴）

### 1. Canvas 2D 渲染引擎
- **PG 做法**：使用原生 Canvas 2D 渲染所有节点和连线，性能极佳
- **CM 现状**：DOM 渲染，节点多时可能出现性能瓶颈
- **借鉴方向**：
  - 当节点数量超过 200+ 时考虑 Canvas 渲染层
  - 或采用混合方案：编辑态用 DOM，浏览态用 Canvas
  - 连线和背景网格可优先迁移到 Canvas 层

### 2. 撤销/重做系统
- **PG 做法**：完整的 Undo/Redo 历史记录，每步操作可回退
- **CM 现状**：有 HistorySnapshot 机制（120 步），但基于快照而非命令模式
- **借鉴方向**：
  - 考虑 Command Pattern 实现更细粒度的撤销
  - 支持操作合并（如连续输入合并为一次撤销）
  - 暴露撤销历史列表供用户浏览

### 3. 自定义文件格式 (.prg)
- **PG 做法**：ZIP 容器 + MessagePack 二进制序列化，比 JSON 节省 40% 空间，支持附件嵌入
- **CM 现状**：纯 JSON 文件存储
- **借鉴方向**：
  - 对于大型脑图，考虑压缩存储（gzip JSON 或 MessagePack）
  - 支持附件/图片嵌入到文档中（当前无图片节点）
  - 保留 JSON 作为交换格式，内部可用更高效格式

### 4. 扩展/插件系统
- **PG 做法**：支持 extension.js 扩展包，可自定义节点类型和行为，最近还在做"重载扩展"功能
- **CM 现状**：无插件系统，功能全部内置
- **借鉴方向**：
  - 设计轻量扩展接口（自定义节点渲染、自定义快捷键、自定义 AI prompt）
  - 利用现有 REST API 作为扩展的通信层
  - 扩展可以是外部进程通过 API 交互

### 5. 多种图类型支持
- **PG 做法**：支持 DAG、树形、逻辑网络、自由连接
- **CM 现状**：以树形思维导图为主，关系线为辅
- **借鉴方向**：
  - 增加"自由画布"模式，节点间可任意连接
  - floating 节点已有基础，可扩展为独立的图模式
  - 支持节点间多对多连接（当前关系线已部分实现）

### 6. 分组框（Section/Group）
- **PG 做法**：支持分组框来组织节点区域
- **CM 现状**：已有 RegionBox 功能 ✓
- **状态**：已实现，可继续优化（如分组折叠、分组内自动布局）

### 7. 跨平台支持
- **PG 做法**：Windows/macOS/Linux 全平台
- **CM 现状**：主要 Windows（Wails 理论上跨平台）
- **借鉴方向**：确保 macOS/Linux 构建正常，CI 中加入多平台测试

### 8. 图片节点 & 附件系统
- **PG 做法**：支持图片节点、附件嵌入到 .prg 文件中
- **CM 现状**：纯文本节点，无图片/附件
- **借鉴方向**：
  - 支持图片节点（拖入图片创建节点）
  - 附件存储在 data 目录下，节点引用路径

### 9. 自动备份
- **PG 做法**：文档变更自动备份，有 auto-backup-v2 机制
- **CM 现状**：有快照系统（snapshots），但需手动触发或定时
- **借鉴方向**：
  - 增加自动备份策略（每 N 分钟 / 每次关闭时）
  - 备份文件带时间戳，支持回溯

## 二、Code Mind 的优势（PG 可借鉴的方向 / CM 应保持的差异化）

### 1. AI 深度集成 ⭐
- **CM 优势**：AI 生成脑图、扩展节点、补全笔记、建议关系线、知识图谱生成
- **PG 现状**：无 AI 功能
- **保持方向**：这是 Code Mind 的核心差异化，应持续深化
  - AI 上下文理解（读取整棵树）
  - AI 多轮对话式规划
  - AI 自动标注优先级/分类

### 2. 节点级 REST API ⭐
- **CM 优势**：完整的 CRUD API、批量操作、片段导入、compact 模式、实时刷新
- **PG 现状**：无外部 API
- **保持方向**：
  - API 是 AI Agent 集成的基础设施
  - 支持 IDE 插件、CLI 工具直接操作脑图
  - 这是"开发者工具"定位的核心

### 3. 面向开发者的工作流
- **CM 优势**：键盘优先、API 驱动、AI 协作闭环（需求→规划→开发→总结）
- **PG 现状**：通用工具，面向设计师/教师/开发者
- **保持方向**：深耕开发者场景
  - 与 Git 工作流集成
  - 代码引用节点
  - 任务状态追踪

### 4. Token 优化（compact 模式）
- **CM 优势**：API 返回可省略 43% 冗余字段，专为 AI 消费设计
- **PG 现状**：无此概念
- **保持方向**：继续优化 AI 友好的数据格式

### 5. 实时刷新机制
- **CM 优势**：API 写入后前端 2 秒内自动检测并刷新，新节点有动画
- **PG 现状**：无外部写入场景
- **保持方向**：这是多 Agent 协作的基础

### 6. 3D 图谱预览
- **CM 优势**：3D 浮动图谱视图，支持搜索、拖拽旋转、跳转
- **PG 现状**：纯 2D
- **保持方向**：作为大型脑图的鸟瞰/导航工具

### 7. 本地优先 + 零配置
- **CM 优势**：exe 即用，数据在本地，无需安装数据库或配置服务
- **PG 现状**：也是本地优先
- **保持方向**：保持极简部署体验

## 三、双方都有但实现不同的功能

| 功能 | Code Mind | Project Graph | 对比 |
|------|-----------|---------------|------|
| 节点拖拽 | DOM 拖拽 + 子树跟随 | Canvas 拖拽 | PG 性能更好 |
| 自动布局 | 层级布局（balanced/right） | 多种布局算法 | PG 更丰富 |
| 主题 | 亮/暗双主题 | 多主题 + 自定义颜色变量 | PG 更灵活 |
| 多语言 | 中/英 | 多语言（含社区翻译） | PG 覆盖更广 |
| 快捷键 | 丰富的键盘操作 | 丰富 + 可自定义图标 | 相当 |
| 导出 | Markdown/TXT | 多格式 | PG 更多 |
| 数据模型 | 树 + 关系线 + 区域框 | 任意图 + 分组框 | PG 更通用 |

## 四、改进建议优先级

### 高优先级（短期可实现，价值大）

1. **撤销/重做优化** — 当前快照机制改为 Command Pattern，支持 Ctrl+Z/Y
2. **图片节点** — 支持拖入图片创建节点，存储在 data/attachments/
3. **自动备份** — 每 5 分钟自动保存备份，保留最近 10 个版本
4. **导出格式扩展** — 支持 OPML、SVG 图片导出

### 中优先级（中期规划）

5. **Canvas 混合渲染** — 连线层和背景用 Canvas，节点保持 DOM（兼顾性能和编辑体验）
6. **更多布局算法** — 径向布局、力导向布局、正交布局
7. **节点类型扩展** — 链接节点、代码块节点、进度节点
8. **多选批量操作增强** — 批量改色、批量设优先级、批量移动到分组

### 低优先级（长期方向）

9. **插件/扩展系统** — 基于 API 的轻量扩展机制
10. **协作模式** — WebSocket 实时多人编辑（与当前 API 轮询互补）
11. **自定义文件格式** — 大文件场景下的压缩存储
12. **跨平台 CI** — macOS/Linux 自动构建和测试

## 六、结论

**Code Mind 的核心竞争力**在于 AI 集成和开发者 API，这是 Project Graph 完全没有的领域。应继续深耕这个方向。

**从 Project Graph 可借鉴的**主要是工程成熟度方面：Canvas 渲染性能、完善的撤销系统、丰富的节点类型、扩展机制。这些是"打磨产品体验"的改进点。

**不建议盲目追随的**：PG 的通用图定位（DAG/网络图）会分散 Code Mind 的开发者工具焦点。保持"思维导图 + AI 协作"的清晰定位更重要。
